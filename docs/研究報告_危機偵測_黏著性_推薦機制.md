## 一、即時接住高危工作人員

### 1.1 研究現況

NLP 偵測自殺風險的表現已**超越人類評估者**（多項指標），且可在**患者未主動揭露**時仍達到可接受的準確率。關鍵突破：

- **BERT + LSTM 多模型**：整合文字語義與時間序列（發話頻率、夜間使用模式），偵測憂鬱/焦慮轉惡。
- **Emory NLP Lab**：專門研究醫療場域中的 AI 心理健康監測，驗證在真實臨床介面可用。
- **Limbic（英國 NHS）**：心理評估分診工具，8 大心理疾患準確率達 93%。

---

### 1.2 隱性危機訊號偵測：不只是「我想死」

研究（ACL 2025 Findings）顯示，大型語言模型在**隱性**自殺意念識別上仍表現不穩。以下是實務上需要抓取的語言特徵：

#### 高風險語言特徵表
| 類別 | 台灣藥師常見例句 | 風險層級 |
|------|-----------------|----------|
| **絕望性語言** | 「這樣下去不是辦法」「再這樣我撐不住」 | 中 |
| **認知窄化** | 「已經沒有選擇了」「只有我這樣吧」 | 高 |
| **自我退出** | 「不想上班了」「反正有沒有我都一樣」「乾脆消失算了」 | 高 |
| **過度自責** | 「都是我的問題」「我真的太爛了」「對不起大家」 | 中-高 |
| **時態崩塌** | 只說過去和現在，**停止談論未來** | 極高 |
| **第一人稱過度** | I/我 的比例遠高於平均（語言學研究顯示與憂鬱強相關） | 中 |
| **絕對化詞彙** | 「永遠」「從來」「沒有人」「所有人」 | 中 |
| **工作-身份解離** | 「我當藥師有什麼用」「救了那麼多人自己卻…」 | 高 |

#### 行為層面訊號（非文字）
- 使用時段異常：凌晨 2–5 點頻繁使用
- 發話量驟降（沉默 > 5 天後突然大量發話）
- 對 bot 說「謝謝你，再見了」帶有終結感

### 1.3 分級回應機制（三層架構）

```
Level 0：一般使用（無觸發）
  → 正常情緒支持流程、金句推薦

Level 1：輕度壓力 / 疲憊
  觸發詞：「累了」「今天很難熬」「壓力好大」
  → 主動提供呼吸練習 / 正念音頻
  → 推薦相關金句 / 歌曲
  → 「想聊聊嗎？」柔性邀請

Level 2：中度倦怠 / 情緒困擾
  觸發詞：「不想上班了」「撐不下去」「感覺沒有人懂」
  → 觸發 check-in 問題：「你最近睡得怎麼樣？」
  → 主動提供 EAP 資源（匿名告知，非強迫）
  → 記錄為關注用戶，下次主動 follow-up
  → 介紹 1925 安心專線（語氣：「你不一定要打，但知道有這個就好」）

Level 3：高危需立即轉介
  觸發詞：「消失算了」「不想活了」「再也不想撐了」
  + 行為異常（深夜使用 + 沉默後突發）
  → 立即切換「溫暖陪伴」模式（不鑄造焦慮）
  → 提供 1925 / 1995 電話，鼓勵當下撥打
  → 給予同理回應後，**不強制**要求用戶提供身份
  → 若用戶已登入帳號，保留紀錄（但不自動通報）
```

### 1.5 倫理框架：匿名用戶的轉介邊界

這是最棘手的問題，以下是目前業界共識：

**原則一：不強制揭露身份**
匿名是安全感的來源。強制實名化反而阻止高危用戶使用。設計應該是：即使匿名，也能接收到資源。

**原則二：「主動告知」優先於「強制通報」**
台灣《心理健康法》目前**未要求**數位平台強制通報（不同於臨床醫師的法定義務）。藥師樹洞的定位是「支持工具」而非「臨床系統」，因此：
- ✅ 主動提供資源
- ✅ 鼓勵用戶自行聯繫專業
- ❌ 不主動通報給用戶單位主管
- ❌ 不在沒有告知情況下追蹤用戶身份

**原則三：設計「知情同意」的例外條款**
在新用戶 onboarding 時，清楚說明：
> 「如果我們偵測到您可能處於危機，我們會主動提供資源。您的資料不會被轉交給您的雇主或任何第三方。」

**原則四：「軟轉介」語氣設計**
錯誤：「您的狀況需要立即就醫。」（觸發防衛）
正確：「聽起來你最近真的很辛苦。有個電話，你不一定要打，但知道有就好——1925，隨時都有人接。」

## 二、增加黏著性

### 2.1 關鍵數據（你的競品研究起點）

| 平台 | 關鍵數據 |
|------|---------|
| **Woebot** | 只有 22% 用戶完成 ≥4 週持續互動（≥3次/週），中位數 9 天 |
| **Wysa（一般用戶）** | 37% 完成第一週，Module 5 後陡降 |
| **Wysa（醫療人員專案）** | 94% 完成至少一次完整會話，80% 回訪，平均 10.9 次會話 |
| **一般心理健康 App** | 下載後 15 天仍在使用：僅 4%；30 天：3% |

**關鍵洞察**：Wysa 在醫療人員群體的表現遠優於一般用戶（80% vs 37%），說明**專屬感**和**職業認同感**是留存的強力槓桿。

---

### 2.2 有效設計模式

#### A. 情感聯繫 > 功能實用性
用戶留存的最強預測因子不是功能多寡，而是**第一次互動是否感覺被理解**。Woebot 的研究顯示：在前 10 天同時使用行為激活（behavioral activation）和認知重建（cognitive restructuring）的用戶，8 週留存率是只用一種的 **3.1 倍**。

設計建議：第一次對話要溫暖、不評判、有反映。不要讓用戶一開始就填量表。

#### B. Check-in 機制設計

**有效的 Check-in 設計（適合藥師）：**
- 時機：下班後 30 分鐘（18:30–20:00 最佳）
- 頻率：每日一次輕量 push，非強迫
- 形式：不要問「你今天幾分？」→ 改用情境問題：
  - 「今天有沒有哪個病人讓你印象深刻？」
  - 「如果今天是一種天氣，你覺得是？」
  - 「今天有沒有讓你想哭或想笑的事？」
- Streak 設計：**不要懲罰中斷**。改為「你回來了！上次你說…你現在還好嗎？」

#### C. 醫療人員特有使用障礙與解法

| 障礙 | 根本原因 | 設計解方 |
|------|---------|---------|
| 怕被同事看到 | 職場污名 | APP icon 設計成「藥師工具箱」樣貌；LINE Bot 顯示名稱可自訂為中性名稱 |
| 時間碎片化 | 班次不固定 | 所有互動模組設計為 < 3 分鐘完成；支援非同步（睡前寫、早上讀） |
| 工作結束才想用 | 在職場不敢打開 | Push notification 設計在下班後；支援耳機 / 靜音模式操作 |
| 「我去用心理 app？太誇張了」 | 自我標籤化 | 重新定框：不叫「心理健康」，叫「藥師的私人充電站」 |
| 輪班護理師凌晨才下班 | 非常規時間 | 支援凌晨使用、不強調「建議你好好睡覺」的說教式內容 |

#### D. 個人化推薦設計

早期個人化（前 3 次互動完成）：
1. **工作類型**：醫院藥局 / 社區藥局 / 藥廠 / 其他
2. **主要壓力來源**：工作量 / 醫病關係 / 同事 / 家庭
3. **偏好的支持方式**：聽 / 說 / 讀 / 做（活動）

這 3 個問題足以讓推薦系統個人化，且不造成用戶負擔。

#### E. 社群元素（需謹慎）

因為匿名性和職場污名，**不建議**在 MVP 階段做公開社群。但可以：
- **匿名心情牆**：其他用戶匿名分享的一句話（非互動式），讓用戶感覺「不只我這樣」
- **藥師投稿金句**：讓用戶貢獻，有參與感但無社交壓力
- V2 後考慮：小組支持功能（同科、同類型藥師限定，邀請制）

### 2.3 LINE Bot vs PWA 黏著性比較

| 維度 | LINE Bot | PWA |
|------|----------|-----|
| **進入門檻** | 極低（台灣 94% 人口用 LINE） | 低（需要開瀏覽器或安裝捷徑） |
| **通知送達率** | 極高（LINE 推播開啟率 ~50%+） | 低（PWA 通知常被忽略） |
| **隱私感** | 低（聊天室格式，感覺被看見） | 高（像獨立 app） |
| **客製化 UI** | 有限（受 LINE 介面限制） | 完全自定義 |
| **多媒體體驗** | 可播音頻、圖片，但體驗受限 | 完整音頻 / 動畫體驗 |
| **離線使用** | 不支援 | 支援 |
| **開發成本** | 低（LINE Messaging API 成熟） | 中（需要前端工程投入） |
| **資料追蹤** | 需透過 webhook，有限 | 完整 analytics 整合 |

**建議策略：MVP 用 LINE Bot，V2 推出 PWA**

LINE Bot 作為「前門」：低摩擦進入、利用現有推播習慣、快速驗證核心功能。
PWA 作為「深度空間」：當用戶想要更私密、更豐富的體驗時，引導到 PWA。

## 三、金句 & 歌曲推薦機制

### 3.1 情緒配對推薦設計

#### 情緒維度模型（Valence × Arousal）

學術上最常用的情緒分類框架，Spotify Audio Features 直接對應此模型：

```
             高喚起 (High Arousal)
                    ↑
   憤怒 / 焦慮      |      興奮 / 快樂
                    |
負向情緒 ←─────────┼─────────→ 正向情緒
(Low Valence)       |         (High Valence)
                    |
   悲傷 / 疲憊      |      平靜 / 滿足
                    ↓
             低喚起 (Low Arousal)
```

#### 用戶情緒輸入 → 推薦策略

| 用戶情緒輸入 | 偵測關鍵詞 | Spotify 參數目標 | 推薦策略 |
|------------|-----------|----------------|---------|
| 疲憊、撐不住 | 累、沒力、好累 | valence: 0.3–0.5, energy: 0.2–0.4 | 先同理情緒（低能量），再緩升（避免刺激） |
| 委屈、想哭 | 沒人懂、委屈、心酸 | valence: 0.2–0.4, energy: 0.1–0.3 | 陪伴型音樂，不強迫振作 |
| 憤怒、不滿 | 幹、去死、幹嘛這樣 | valence: 0.2–0.4, energy: 0.6–0.8 | 先認可憤怒，再提供出口 |
| 還好、普通 | 還行、還好啦、普通 | valence: 0.5–0.7, energy: 0.4–0.6 | 輕快日常型 |
| 有點快樂 | 今天還不錯、開心 | valence: 0.7–0.9, energy: 0.5–0.7 | 強化正向情緒 |

#### 「同理優先」vs「提振優先」原則

研究顯示，情緒困擾時直接推「振奮歌曲」會讓用戶感覺被忽視。推薦策略應分兩段：

1. **第一首（陪伴）**：與用戶當前情緒接近（情緒同理）
2. **第二首（引導）**：valence 稍高、energy 稍升（溫和提振）

可讓用戶自選：「想繼續陪著這個心情，還是試試看輕一點的感覺？」

### 3.2 Spotify API 技術可行性

**MVP 可行方案：**

```python
# Spotify API 情緒推薦核心邏輯
import spotipy
from spotipy.oauth2 import SpotifyClientCredentials

sp = spotipy.Spotify(auth_manager=SpotifyClientCredentials(
    client_id="YOUR_CLIENT_ID",
    client_secret="YOUR_CLIENT_SECRET"
))

def get_mood_tracks(valence_target, energy_target, market="TW"):
    results = sp.recommendations(
        seed_genres=["mandopop", "taiwanese-pop", "indie"],
        target_valence=valence_target,
        target_energy=energy_target,
        min_popularity=30,
        market=market,  # 台灣市場
        limit=5
    )
    return results["tracks"]
```

**技術注意事項：**
- Spotify API 速率限制：部分端點 1 req/sec，需要**快取推薦結果**（同情緒段的推薦可複用）
- 台灣版權：`market="TW"` 確保回傳在台灣可播放的歌曲
- Embed 方式：`<iframe src="https://open.spotify.com/embed/track/{track_id}">` 可直接嵌入網頁，不需要用戶登入 Spotify
- 若用戶沒有 Spotify：提供 YouTube 備援連結（使用 YouTube Data API 搜尋同曲名）

**Spotify vs YouTube 選擇：**

| | Spotify Embed | YouTube Embed |
|---|---|---|
| 台灣普及率 | 中（付費用戶有限） | 高（幾乎所有人都有） |
| 播放完整度 | 30 秒預覽（免費）/ 完整（登入） | 完整 |
| API 複雜度 | 中 | 低 |
| 廣告干擾 | 無（embed） | 有（非 Premium） |

**建議**：預設 YouTube embed，提供「在 Spotify 收聽」的跳轉連結。

### 3.4 「不想聽推薦」的逃脫出口設計

這個設計至關重要——強迫推薦反而是最快讓用戶流失的方式。

**每次推薦後必須提供的選項：**

```
🎵 [歌曲名稱] — [歌手]
   ▶ 播放預覽    📌 先記起來

───────────────
📱 今天不想聽歌
🎲 換一首
🗂️ 想自己選風格
❌ 跳過，繼續聊聊
```

**設計原則：**
- 「不想聽」永遠是第一個逃脫出口，且不帶評判
- 按「跳過」後，bot 的回應：「沒關係，那我們就繼續聊聊今天的事。」（不追問為什麼不喜歡）
- 三次跳過後：靜默學習，下次調整推薦風格，不詢問用戶

**金句同理：**
- 每則金句下方有 👍「這句說到心坎」/ 👎「換一句」
- 按了「換一句」不需要解釋，直接換

## 四、MVP vs V2 功能地圖

### MVP（第一版，建議 3–4 個月完成）

| 功能 | 優先級 | 說明 |
|------|--------|------|
| **三級危機偵測（關鍵詞觸發）** | 🔴 必做 | 不需要 ML，先用規則型關鍵詞清單 |
| **Level 3 觸發 → 1925/1995 推薦** | 🔴 必做 | 語氣溫暖，非強制 |
| **情緒快速 check-in（3 選項）** | 🔴 必做 | 每日推播，< 1 分鐘完成 |
| **情緒 → 金句配對（基礎版）** | 🔴 必做 | 5 種情緒 × 10 則金句 = 50 則資料庫 |
| **情緒 → 歌曲推薦（YouTube embed）** | 🔴 必做 | 5 種情緒 × 5 首歌的預設清單 |
| **跳過 / 換一首的逃脫出口** | 🔴 必做 | 無推薦強制性 |
| **LINE Bot 介面** | 🔴 必做 | 低摩擦進入 |
| **藥師專屬語境的 onboarding** | 🟡 建議做 | 3 個快速個人化問題 |
| **匿名投稿金句入口** | 🟡 建議做 | 建立社群感 |

### 語氣指南（避免踩雷）

❌ 不要說：「你需要立即尋求專業協助。」
✅ 說：「聽起來你現在很難受。有些人在這種時候會打 1925，那邊的人不會評判你。」

❌ 不要說：「你這麼優秀的藥師，一定可以撐過去！」
✅ 說：「辛苦了，能說說今天發生了什麼嗎？」

❌ 不要推薦完不給逃脫出口
✅ 永遠有「跳過」選項，且第一個顯示

### 數據驗證指標（MVP 上線後追蹤）

- **日活用戶 / 月活用戶比率**（目標 > 15%）
- **Level 2+ 觸發後的資源點擊率**（初期目標 > 10%）
- **金句 / 歌曲「換一首」vs「👍」比率**（調整推薦準確度）
- **7 天留存率**（業界中位 ~37%，針對醫療人員有機會達 50%+）
- **用戶投稿金句數量**（社群參與健康指標）
