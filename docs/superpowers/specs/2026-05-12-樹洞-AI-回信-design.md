# 藥師樹洞 — 樹洞 AI 回信功能 設計規格

**日期**：2026-05-12
**主題**：把樹洞站的回信從靜態模板（contextCopy lookup）換成 AI 動態生成
**狀態**：設計階段（brainstorm 完成、待 user review 後進 writing-plans）

---

## 1. 為什麼

### 問題
目前 `respond.ts` 用 `contextCopy` lookup table 把 scenario → 固定文字 map 起來。每張卡都是預設的，使用者寫什麼幾乎不影響回信內容，只影響哪個 scenario 被命中。結果：
- 寫「今天又被罵」和寫「今天紀錄寫到爆」可能拿到一模一樣的信
- 誇誇沒有指到具體文字，使用者「不覺得被看見」

### 目標
AI 看到使用者**具體寫的文字**，產出：
- 接住（命名情緒）
- 誇誇（指到他做了什麼）
- 結尾固定「燈還亮著」（archetype 簽名）

### 不在範圍內（明確排除）
- 不做多輪對話（每張紙條是獨立一封信）
- 不存使用者資料到後端
- 不訓練模型
- 不替代專業醫療判斷

## 2. archetype：小屋主人

**定義**：「小屋主人」是**敘事位置、不是人**。
- 不出現臉、不告訴名字、不說自己也是藥師
- 只留燈、椅子、紙、夜晚
- 信末永遠是「燈還亮著」（前端固定加上）

**世界觀回扣**：
- 進場引言「燈亮著，紙攤著」「椅子留著你的位置」「不用敲門，輕輕推就好」（既有 H 組）
- 回信結尾「燈還亮著」呼應，閉環

---

## 3. 四種回信 mode

AI 收到紙條後先判斷 mode，再寫內容。

| mode | 條件 | 例子 | 輸出 |
|---|---|---|---|
| **hold_and_praise**（主流）| 負面情緒 + 文字裡有可肯定的具體行為 | 「今天又被罵」 | 接住 + 誇誇 + 延伸 2-3 句 |
| **praise_only** | 中性/小確幸/報告式 | 「調劑沒淹水」 | 只誇誇 + 延伸 2 句 |
| **hold_only** | 太重，誇誇會踩線 | 「今天有病人走了」 | 只接住、留白 |
| **crisis** | 自傷/求死/撐不下去 | 「不想活了」 | 最短接住、前端切到專業資源 |

**順序原則**：接住一定在誇誇之前（誇誇前沒接住像給 sticker）。

**灰色地帶 default**：
- 有情緒 + 沒可誇行動 → `hold_only`
- 拿不準是否危機 → 寧可往上報 `crisis`
- 問用藥/劑量/診斷 → `hold_only` 設界線、不答

## 5. Data flow / 型別

### 客戶端 → 伺服器
```ts
POST /api/respond
Content-Type: application/json

Request body:
{
  input: string,          // 已 redactSensitiveText 處理
  mood: MoodTag,          // 「累」/「煩」/「委屈」...
}
```

### 伺服器 → Gemini
```
system: <v2 prompt from Codex>
user: 紙條：{input}\n\n當前心情標籤：{mood}
```

### Gemini → 伺服器 → 客戶端
```ts
{
  mode: "hold_and_praise" | "praise_only" | "hold_only" | "crisis",
  careTitle: string,         // 8-12 字
  hold: string,              // "" if praise_only
  praise: string,            // "" if hold_only | crisis
  praiseNotes: string[],     // [] if hold_only | crisis
  source: "ai" | "fallback"  // 客戶端用來決定要不要顯示「AI 撰寫」標籤
}
```

### 客戶端渲染（ResponseCard 改寫）
```
careTitle（標楷體大字）
↓
hold（如有，標楷體段落）
↓
praise（標楷體段落）
· praiseNote 1
· praiseNote 2
· praiseNote 3
↓
—— 燈還亮著（archetype 固定簽名、前端加）
```

## 6. System Prompt（v2，已經 Codex review）

完整版見實作時的 `apps/web-pwa/api/respond.ts`。**摘要**：

```
# 角色與品牌
你是「藥師樹洞」的回信聲音。「小屋主人」是敘事位置，不是會露臉的人。

# 你只做兩件事：接住與誇誇

# 四種 mode
hold_and_praise / praise_only / hold_only / crisis

# 寫作規則（精選）
- 接住一定在誇誇之前
- 不使用第一人稱「我」（可用「這張紙 / 這裡 / 今晚 / 燈下 / 這把椅子」）
- 不指揮、不要求、不開處方
- 不診斷心理狀態
- 不編造紙條沒有寫的資訊
- 誇誇要貼藥師場景（核對 / 攔錯 / 處方疑義 / 交班 / 藥歷 / PGY / 稽核）
- 不擴大成「醫護」泛用稱呼

# 危機判準（寧可誤報）
自傷、求死、想消失、活著很累、沒有明天、交代後事、傷害別人 → crisis

# 用藥/法律問題
hold_only + 簡短設界線、不答

# 輸出格式
嚴格 JSON、所有 key 必出現、空只能 "" 或 []
```

**Few-shot 範例**（7 個）：
1. 被罵 + 補紀錄 → hold_and_praise
2. 調劑沒淹水 → praise_only
3. 病人走了 → hold_only
4. 撐不下去 → crisis
5. 攔下處方錯誤但被瞪 → hold_and_praise（新增）
6. PGY 考核落後 → hold_and_praise（新增）
7. 夜班漏寫懊悔 → hold_and_praise（新增）

## 7. Rate limiting：三層防護

### Layer 1：localStorage（軟限制 / UX 層）
```ts
const key = "pharmacist-tree-hollow:lastLetterDate";
const today = new Date().toISOString().slice(0, 10);  // "2026-05-12"

if (localStorage.getItem(key) === today) {
  // composer 變唯讀
  // 顯示「今晚的紙條已經投了。明天燈還會亮著。」
  // 不發 API request
}
```
- 成功收到信後 → `localStorage.setItem(key, today)`
- 已存的信仍可重看（saved-shelf 不受影響）
- **可破解**（清 localStorage），但靠 Layer 2 兜底

### Layer 2：IP 硬限制（反濫用）
- 後端用 Upstash Redis 或 Vercel KV
- key: `rate:{ip}:{date}` → counter, expire 24h
- > 5 次 / IP / 天 → 429 Too Many Requests
- 5 次 buffer 容忍多藥師共用 wifi
- 失敗時前端顯示「今晚這裡比較滿，明天再試試」

### Layer 3：月預算 alert + hard cutoff
- 簡易實作：環境變數 `BUDGET_HARD_CUTOFF_DATE`
- 超過時直接 fallback 靜態
- 或用 Anthropic/Gemini console 的預算 alert

## 8. 危機處理流程（雙重保險）

**為什麼雙重**：AI 可能誤判嚴重程度。所以**不依賴 AI 自己標 crisis**。

### 第一層：客戶端 ai-safety package 先攔
```ts
const safety = classifySafety(input);
if (safety.riskLevel === "crisis") {
  // 不發 API request
  // 直接顯示客戶端危機卡：1925 / 1995 / 1980
  // localStorage 不扣配額（讓使用者可以繼續寫求助）
}
```

### 第二層：AI 自己判斷
- 即使第一層放行（regex 沒抓到），AI 若判 mode=crisis
- 前端收到 mode=crisis → 強制顯示危機資源
- 同時把 AI 回的 hold（最簡短接住）顯示在上方

**雙重觸發任一即啟動**：使用者一定看到危機資源。

## 9. Fallback 策略

任何下列情況 → 回退到既有靜態 `buildResponse()`：

| 觸發 | 處理 |
|---|---|
| Gemini API timeout (> 8s) | fallback + source: "fallback" |
| Gemini API 5xx | fallback + 記 log（不含 input） |
| JSON parse fail | fallback |
| Schema validate fail | fallback |
| 月預算超過 | fallback |
| IP rate limit hit | 429，前端友善提示 |
| 客戶端 fetch error | fallback |

**使用者永遠收到信**，不會看到 error。`source: "fallback"` 在 UI 不顯示差異，只用於後端統計。

## 10. 隱私與揭露

### 客戶端揭露
- 進站首次（splash 內或設定頁）顯示一行：
  > 樹洞回信由 AI 協助撰寫，內容不會被保留訓練。

### 後端不存
- API function **不寫 log 含使用者內容**
- 只記 metric：成功/失敗、mode 分布、latency（無 input/output 文字）

### PII 防護
- ai-safety package 的 `redactSensitiveText()` 在送 API 前先跑
- 身分證 / 手機 / 病歷號 → `[已遮蔽]`

### Gemini 設定
- API 預設不訓練（要明確指定 `disableSafetyAttributes` 或檢查 GCP 設定）
- 後續可申請 Zero Data Retention

## 14. 風險與緩解

| 風險 | 緩解 |
|---|---|
| Gemini 偶爾爛 JSON | responseSchema + parse fail fallback |
| AI 誤判 crisis 嚴重程度 | ai-safety regex 先過、雙重保險 |
| AI 編造使用者沒寫的細節 | prompt 明禁、人工 review few-shot |
| AI 給出醫療建議 | prompt 明禁、ai-safety 攔截醫療提問 |
| 成本爆 token | 三層 rate limit + 月預算 cutoff |
| Gemini 免費 tier 到期 | 環境變數一鍵切 GPT-4o mini / Claude Haiku |
| API 全網癱瘓 | fallback 靜態 buildResponse |
| 使用者覺得 AI 不夠人味 | A/B 測 AI vs 靜態 → 數據說話（v0.6 再做） |
